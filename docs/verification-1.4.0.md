回归覆盖无新版、新版、旧版及预发布版、断网、限流、损坏下载、包内版本不符、缓存篡改、安装失败回滚、崩溃恢复、并发检查和安装互斥。项目场景包含忙碌项目延后、仅用全局技能的项目保留旧规则、离线项目恢复、跨版本补齐和暂停任务保护。

## 复测中修正的问题

首轮真实任务暴露了一个问题：`trellis init` 自带但尚未开始的 `00-bootstrap-guidelines` 被当成正在工作的任务，导致升级一直延后。现只排除符合默认模板、未选中且没有启动证据的占位任务；实际开始、被选中或明确暂停的任务仍受保护。修复后重新执行了上述A/B任务，并增加专项回归。

A使用的是暂停状态判定最后修正前的候选包；B安装的模拟1.4.2包含最终源码。最终代码的50项自动化检查均已通过。不能把首轮延后安装说成完整通过。

## 结果的适用范围

1. 测试环境为 Windows、PowerShell 7、Python 3.10以上和真实 Codex 主任务；受控 Release 用于验证升级过程，真实联网检查单独验证。
2. 技能由 Codex 按入口规则执行，不是操作系统的常驻服务。暂停、询问进度、关闭软件或单纯推送 GitHub不会新增安装动作；计划模式只检查。
3. 自动更新可能留下未提交的项目技能文件。A/B的业务代码、任务归档和日志已经提交；不能据此声称升级后的整个工作树仍然干净，也不会为了这些托管文件重复已通过的业务质量检查。
4. 本机首次升级同样跳过尚未收尾的真实业务项目，不能以强制覆盖或归档别人的任务来伪造“全部项目已更新”。旧会话没有重新加载入口规则时，后续正常继续任务或新任务会接手待更新处理。
